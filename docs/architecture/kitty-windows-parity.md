# Kitty-style Windows terminal parity (#1282)

This is the acceptance matrix for [issue #1282](https://github.com/zackees/clud/issues/1282). The reference is the tracked NixOS [Kitty configuration](https://github.com/zackees/nixos/tree/main/home/kitty): `kitty.conf`, `tab_bar.py`, `window_title_bar.py`, `paste.py`, and `keys.py`, plus the `kitty --single-instance` desktop launcher. The requested Windows entry point is `clud --kitty-term`. “Configured” below means present in the feature worktree's source; it does not mean a native Windows GUI has passed the check.

## Candidate and boundary

The library-only `wezterm-term` spike could parse terminal state but did not provide a complete desktop GUI: it leaves window creation, rendering, input integration, tabs/panes, and clipboard behavior to a host application. The candidate therefore uses a pinned native WezTerm GUI fork with its ConPTY path and Kitty keyboard/graphics support. `clud --kitty-term` launches the bundled GUI with an isolated Lua config and forwards the original clud invocation into its first pane. The CLI removes the outer `--kitty-term` before forwarding and uses `CLUD_KITTY_TERM` as its recursion guard. It is explicit and Windows-only; [the existing `--web-term` path](web-terminal.md) remains separate.

The source contains CLI parsing and launch dispatch, a Lua configuration, a Rust clipboard paste helper, and a wheel bundle helper. The bundle requires the GUI, ConPTY/OpenConsole and graphics DLLs, license notices, `SOURCE_REVISION`, and the paste helper together under `clud-kittyterm` at the wheel data scheme location described below. The packaged fork is pinned to `0be809bc0d2d82143efa5684ad3e0d76d879ce9e`. Merged fork [PR #5](https://github.com/zackees/wezterm/pull/5) allows `--return-initial-exit-code` together with auto-connect, so a launcher that reuses an existing GUI returns its spawned pane's exit status; its Windows build, tests, and portable packaging passed in [run 36046678431](https://github.com/zackees/wezterm/actions/runs/36046678431). Earlier merged fork [PR #4](https://github.com/zackees/wezterm/pull/4) resolves the published GUI socket against its actual runtime directory when the second launcher has a different cwd. Earlier merged fork [PR #3](https://github.com/zackees/wezterm/pull/3) preserves the launching process PATH when creating a Windows PTY while retaining registry-only directories. The fork's [public prerelease](https://github.com/zackees/wezterm/releases/tag/kitty-windows-compat-0be809bc) provides the durable `WezTerm-windows-portable.zip` asset. The ZIP has SHA-256 `933c3a0ed459b9b19dcb79b47e94d8583866271fa8fb7a0c2121aab1bcc82b5a`, and its `SOURCE_REVISION` names the pinned commit. Earlier merged fork [PR #2](https://github.com/zackees/wezterm/pull/2) allows an explicit config to publish/discover only when its absolute config path matches, retains pane exit statuses, and exposes `WaitPaneExit`, allowing a launcher that reuses an existing GUI to wait for its newly spawned pane rather than for the GUI process. Windows ARM64 is explicitly unsupported because no ARM64 GUI bundle is packaged.

Wheel installation now places the portable bundle under `.data/data/clud-kittyterm/`, which maps to the environment prefix beside `Scripts/` on Windows. Wheel installers reject a directory under `.data/scripts/`; the launcher, installed-wheel checks, and native smoke test all resolve the prefix data location. A real Windows wheel from CI run 35943755956 was repacked with the corrected layout, passed the Windows wheel checker, and installed using uv's Windows platform mode. Final native installed-wheel validation is recorded on clud PR #1293.

A read-only feasibility check found no `/dev/kvm` device for a local Docker Windows VM; no VM was launched or downloaded. The issue owner accepted native headless Windows CI as the automated gate. It verifies the real GUI executable can create a pane, run a child, and propagate its exit status; the fork separately tests reused-GUI pane-status retention and RPC behavior. Visible pixels, physical keyboard behavior, clipboard interaction, and drag interactions remain explicit manual limitations rather than claims made by this implementation.

## Verification gates

1. Record the native Windows build, wheel/version, fork `SOURCE_REVISION`, command line, and output. The accepted automated gate runs the packaged GUI executable and child on a hosted Windows runner; it does not claim visible-pixel or physical-input coverage.
2. Reproduce Kitty and WezTerm failures separately at process start, GUI creation, ConPTY shell, and protocol layers. Capture exact error and lowest failing layer before attributing a cause.
3. Verify bundle layout, license notices, wheel `RECORD`, and installed paths on Windows. Run the wired CI jobs against the published fork ZIP and confirm the pinned digest and revision checks pass. Ensure no independently installed WezTerm is shadowed and `--web-term` still launches by its existing contract. Verify initial-pane exit propagation in the packaged GUI smoke and reused-pane propagation in the fork tests.
4. Use a controlled native Windows desktop for any future claims about visible rendering, physical keyboard/mouse behavior, clipboard interaction, or cross-window dragging. Until evidence is recorded, those rows remain explicitly partial or unverified.

The installed-GUI smoke also has a bounded headless semantics stage after the
shared-GUI and independent-exit checks. It exercises ConPTY size changes, raw
ETX delivery, alternate-screen entry/restoration, truecolor style retained in
escaped pane text, bracketed-paste framing, heavy output through a final
sentinel, and Kitty keyboard/graphics query replies. These probes are pending
native CI validation; source checks alone do not establish a pass. Raw ETX is
not a physical Ctrl-C key event. CLI text injection does not prove key
press/repeat/release behavior. The graphics reply proves protocol negotiation,
not image pixels; escaped text proves style state, not visual contrast.
Physical mouse events, clipboard interaction, drag, and pixel rendering remain
outside headless evidence.
